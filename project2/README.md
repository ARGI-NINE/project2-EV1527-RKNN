# project2: EV1527 Unknown-CLK Decoder

这个项目用于从 `wav` 录音中解码 EV1527 数据，满足你提出的约束：

- 接收端不知道发送端频率（CLK 未知）。
- 按 EV1527 固定结构做匹配：`sync + 20位地址 + 4位数据`（共 25 组高低电平）。
- 依据 `12T高 + 4T低 => 1`、`4T高 + 12T低 => 0` 做判决。
- 使用你给定的时基：`sync = 4T高 + 124T低`，并强制 `4T <= 单次翻转间隔 <= 124T`（去毛刺基础约束）。
- 要求 `sync` 的首个低电平是本帧内最长低电平。
- 对每帧给出置信度。
- 通过重复帧聚类增强稳定性（EV1527 会重复发送同一帧）。
- 对空闲时长翻转、噪声毛刺做抑制。

## 文件

- `ev1527_decode.py`：主解码脚本（纯 Python 标准库，无第三方依赖）

## 运行方式

在仓库根目录执行：

```powershell
.\.venv\Scripts\python.exe .\project2\ev1527_decode.py --wav .\capture03.wav --start-sec 90 --top 10
```

你给出的提示是“数据大致在 1分30秒以后”，所以默认建议从 `--start-sec 90` 开始。

如需保存详细结果：

```powershell
.\.venv\Scripts\python.exe .\project2\ev1527_decode.py --wav .\capture03.wav --start-sec 90 --json-out .\project2\decode_result.json
```

## 核心算法说明

1. 读取 WAV（支持 PCM 和 IMA ADPCM）。
2. 多组预处理并行尝试：
   - 原始波形平滑（多窗口）
   - 固定阈值二值化：`>=0` 判高电平、`<0` 判低电平
   - 短毛刺 run 合并（去抖）
3. 在二值 run 序列中搜索候选帧：
   - 先找 `sync_high + sync_low`
   - 再取后续 `24` 个 bit 的 `high/low` 对（总共 50 runs）
   - 估计未知 `T`，并约束在 `230us ~ 4.24ms`
4. 逐位比较 `0/1` 两种时长模板，取误差更小者作为 bit 判决。
5. 置信度综合：
   - 位时长拟合误差
   - bit 周期抖动
   - sync 误差
   - sync 低电平是否为本帧最长低电平
6. 跨配置去重后做重复帧聚类：
   - 近似码字（小汉明距离）+ 接近 CLK 合并
   - 输出更稳的“簇中心码字”和重复次数

## 常用参数

- `--start-sec` / `--end-sec`：限定搜索时间范围
- `--min-frame-confidence`：提高可减少误报，降低可增加召回
- `--min-occurrences`：最少独立出现次数（默认 `3`）
- `--min-burst-occurrences`：同一短时突发窗口内最少出现次数（默认 `3`，用于体现 EV1527 重发特性）
- `--top`：输出前 N 个候选簇
- `--json-include-all-clusters`：导出 JSON 时包含全部簇（默认仅导出满足重复约束的簇）
- `--verbose`：查看每组预处理配置的中间统计

## 结果怎么选

输出里有两个关键指标：

- `occ`：同一簇的“独立出现次数”（按时间去重后）
- `avg_conf`：该簇平均置信度

建议优先选择 `occ` 更高且 `avg_conf` 不低的簇；如果 `occ` 都是 1，优先看更高 `avg_conf`，并适当扩大/缩小时间范围再次验证。

另外会输出 `Activity bursts`：这是仅基于“短时内候选帧密度”的时间窗口，不依赖码字稳定性。  
当噪声较大、码字不稳定时，先用它定位真实发放时间段，再做细化判决。

## 说明

- 此脚本故意使用“多配置 + 聚类”策略，目的是在噪声、空闲翻转和未知 CLK 的情况下提高稳定性。
- 当前 `capture03.wav` 采样率为 `8000Hz`（即每个样本 `125us`），解码误差模型已按该采样量化步长做容差处理。
- 若你后续提供更多标注样本（已知正确码字和时间段），可以再把评分权重和阈值做针对性收敛，进一步提高准确率。
